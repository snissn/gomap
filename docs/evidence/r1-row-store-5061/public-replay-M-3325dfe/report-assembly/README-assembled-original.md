## Current findings, correctness and remaining limits

Root’s A acceptance explicitly retains the typed checkpoint allocation increase: **1,110,120→3,829,760 B for one checkpoint call (+2,719,640 B; 3.45×)** and **5,849→6,534 allocations (+685)**. Timing is **INCONCLUSIVE** on both sides. Baseline already includes a **3,935,272 B** sample, above the candidate maximum; that overlap does not dismiss the median increase or identify its cause. Whole-process sampling and cumulative end-of-cell counters cannot attribute the additional work. **Causal attribution remains UNRESOLVED**; root accepts the visible cost within this finite profile. BSON read-view setup similarly rises **1,264→3,512 B/call (+2,248 B)** while allocations fall **12→11**; its timing remains inconclusive. These are setup/maintenance observations, distinct from steady returned-row costs. See [the original A decision](../../../../docs/evidence/r1-row-store-5061/_artifacts/final-M-3325dfe/results/A/root-cost-acceptance-original.json).

The selected C sweep crosses bio widths **96/4096 bytes**, actual request sizes **1/32 rows**, absent/email+city indexes and bio/email+city changes: **4096 live rows, 100 serial mutation requests and five fresh-DB repetitions in each of 16 groups (80 cells)**. All 80 original Flush/reopen full-row, current-posting and historical-posting oracles pass. Every cell records **100 UpdateBatch calls, 100 WAL appends, 100 logical syncs and 100 actual file-sync calls**; item counts are 100 or 3200. ACK includes publication.
