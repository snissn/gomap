# Public outer guard source prototype

External source prototype for independent safety review and subsequent maintained landing. Bounded synthetic safety results, when present, are recorded below; no database workload or build is part of this constructor task. Owns one existing child invocation; it does not implement a workload or replace lifecycle consumers. Use a dedicated fresh Python process, fresh guard output directory, and fresh separate campaign output. Never use the sealed profiling runner/namespace.

Proposed command shape, **not executed**; retain the complete frozen campaign environment from `review/public-ab-plan.md` (`BUILD=false`, `BUILD_GOYCSB=false`, `TARGETS=treedb_mongo`, no Mongo rerun, original client/ELF/manifests/workload, unset GOMAXPROCS). `OUT_DIR` selects campaign output; guard output must be separate so the maintained shell sees an empty output directory:

```sh
OUT_DIR=/mnt/fast4tb/OWNED/FRESH-CAMPAIGN \
python3 -B /mnt/fast4tb/gomap-mongo-perf-graph-6a9s7h58/prototypes/public_guard_source/public_guard.py \
  --scripts-dir /absolute/frozen/source/scripts \
```

Default resource contract is 24 GiB aggregate RSS of live **owned descendants** (not guard's own RSS) and 10 GiB account-available filesystem space, using `statvfs.f_bavail * f_frsize`. Resource overrides exist for synthetic controls; changed values are not the fixed public campaign. Samples are at most 200ms apart plus sampling/scheduling overhead; brief peaks and exited children can be missed. Neither continuous enforcement, complete lifetime RSS nor unperturbed timing is proved. New child stdout/stderr logs and timestamped resource/process samples remain retained. There is no 1 GiB evidence cap, full-census scanning, raw artifact copying, deletion or automatic retry.

Safety model: require a dedicated childless supervisor, enable Linux PR_SET_CHILD_SUBREAPER, start root in a fresh session and pin its pidfd before any poll/wait. Discovered descendant ownership requires direct supervisor parenthood (including adopted orphan) or a still-live pinned parent at pin time. After the final proc start-token/parent snapshot, a nondirect child's **own new pidfd must still be live** before installation: fd(A)/proc(B) races reject and close that fd, leaving no mismatched row. Direct/adopted children remain ours and unreaped, so quick-exit zombies retain their separate PID-reservation proof. Verify PID/start ticks and retain process-group/session observations; track pinned children after reparenting/setsid. Retire exited pidfds before allowing a recycled numeric PID to be newly adopted through independent lineage. Root stays unreaped until terminal checks, so its PID cannot recycle. Immediately after pin, retain `root.identity.json` with PID/start ticks/PPID/group/session; final result repeats that identity and original-shell TERM names its start token even for a root absent from live RSS samples. No executable hash is required for cleanup because ownership survives exec; campaign source/ELF bindings remain with original consumers.

Cleanup sends TERM to the original shell first, allowing its original trap/checked owner Close. Any intervention is RED. After grace, signal remaining task-owned group/session members individually via retained pidfds, TERM then KILL, rediscovering adoptees between passes. **Never killpg, bare PID kill, process-name kill, or signal an unrelated group.** This covers groups created by maintained helper `start_new_session=True` while avoiding PGID recycling authority. Unpinned launch fallback is restricted to the exact direct unreaped Popen child via the maintained helper. Failed observation falls back to known pinned cleanup and retains discovery errors; it cannot certify that an unobservable child was cleaned. Exited adopted children are reaped with `waitid(P_PIDFD, fd, WEXITED|WNOHANG)`, never numeric waitpid; ECHILD means that exact pinned task was already reaped. Require Python P_PIDFD/waitid and preflight kernel support using the supervisor's own nonchild pidfd (expected ECHILD). Unsupported platform fails before launch, without a numeric-reaping fallback. Original root stays with its unreaped Popen owner, and original launcher remains responsible for its checked statuses. Live descendants after root exit0 veto green.
