## Inspected maintenance flow and safety boundaries

The offline `treemap compact DB -rw -json -mode full|quick|exhaustive` route resolves the database layout and uses supported `OpenBackend`, which applies persisted format options and installs stable dictionary resource authority for the maintenance lifetime ([CLI route](/private/tmp/gomap-qs-5005-verify/TreeDB/cmd/treemap/main.go:530), [OpenBackend](/private/tmp/gomap-qs-5005-verify/TreeDB/open_backend.go:23)). The prior #4886 failure is closed; this report does not treat that prerequisite as unresolved. The inspected cached outer-leaf path deliberately rejects exhaustive; close the public owner before using the offline backend route ([cached contract test](/private/tmp/gomap-qs-5005-verify/TreeDB/compact_storage_test.go:16)).

The existing narrower command is `treemap leafgen-gc DB -rw -json`, optionally `-dry-run`. It opens public cached TreeDB, checkpoints and merges cached protected roots, then calls backend GC ([CLI](/private/tmp/gomap-qs-5005-verify/TreeDB/cmd/treemap/leaf_generation.go:186), [wrapper](/private/tmp/gomap-qs-5005-verify/TreeDB/leaf_generation_gc.go:49)); dictionary authority comes through cached SetDictStore. It is supported but includes public reopen/close effects. There is no existing backend-only leaf-GC CLI route. `compact -mode quick` is a supported backend alternative but can pack once and vacuum, so it is not strictly GC-only.

`CompactStorage` holds a pre-maintenance snapshot through index vacuum to keep leaf sources readable, performs value-log GC/rewrite work, then leaf packing, leaf GC, index vacuum, settling GC, and a final audit. Exhaustive additionally seals the current leaf generation before packing and forces leaf-pack eligibility. Successful packs checkpoint; successful vacuum releases the pre-maintenance leaf guard. Settling runs at most four passes. Newly packed output is excluded from repacking within the same invocation ([snapshot guard](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:496), [seal and pack](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:573), [settling](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:941), [output exclusion](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:1339)).

Reachability has distinct layers:

- Current and registered protected user/system roots keep their reachable generations live.
- Independently recoverable durable roots retain recovery-only generations as retiring. Recoverable-root capture includes both durable slots and pending/ambiguous resource closure; it is revalidated before destructive work.
- Snapshot generation pins and physical stable-resource pins can also defer removal. A reported generation `PinnedCount=0` does not prove its files are outside every recovery resource set.

The real leaf-GC decision consults recoverable reachability before deletion and explicitly labels recovery-only generations retiring ([GC capture](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_gc.go:111), [recovery retention](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_gc.go:496), [recoverable closure](/private/tmp/gomap-qs-5005-verify/TreeDB/db/recoverable_root_set.go:224)). The final compact audit instead derives eligible debt from current/protected reachability and generation pins without consulting that recovery closure ([audit](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage_audit.go:863)). Its leaf-GC debt can consequently be retained bytes rather than bytes currently deletable by applied GC. This semantic difference does not authorize deleting the bytes or setting completion flags true: existing tests require retained packed sources to remain reported debt ([test](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage_test.go:2626)).

Checkpoint seals previously published state and explicitly does not advance CommitSeq. Repeating checkpoint alone need not overwrite the older durable fallback. A successful durable publication updates one target slot and releases that slot's former resource set ([checkpoint contract](/private/tmp/gomap-qs-5005-verify/TreeDB/db/db.go:3918), [slot replacement](/private/tmp/gomap-qs-5005-verify/TreeDB/db/durable_root_runtime.go:1851)). The rehearsal's four zero-eligible settling passes are consistent with that behavior. Source plus observed retiring counts support legitimate recovery retention; a physical resource leak has not been demonstrated.

## Policies, automatic maintenance, and scale limits

Full/quick value rewrite defaults use 30% stale ratio and an 8 MiB stale-byte floor, with the default floor capped by the ratio for small segments. Exhaustive uses any stale byte and forces leaf packing. Default pack-pass limits are quick 1, full 32, exhaustive 256; copied-byte limits per pass are quick 256 MiB, full 1 GiB, exhaustive unlimited. The rehearsal explicitly used 64 passes. Ordinary explicit leaf packing defaults to a 10,000 ppm reclaim-per-copy threshold and frame K=16 ([rewrite policy](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:1134), [normalization](/private/tmp/gomap-qs-5005-verify/TreeDB/db/compact_storage.go:1088), [pack defaults](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_pack.go:20)). Exhaustive can scan/copy substantially more live data; decoded copy bytes are not physical bytes reclaimed.

The hot/warm/cold cached generation loop offers maintenance every second, with a GC opportunity every fifth tick, subject to admission. GC has a 1 MiB minimum, a 90-second interval and a three-minute no-op interval; rewrite has a 30-second interval and 15-second stage-confirm delay. Source constants set rewrite triggers of 4 GiB total bytes and 20% stale, a 128 MiB/s rewrite budget, 50% staged per-segment stale selection versus 85% generic selection, and a 30-second minimum segment age ([cadence](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:10096), [rewrite defaults](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:10157), [loop admission](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:19450)). These are source defaults, not proof that this rehearsal exercised them or that storage has a hard bound.

Automatic outer-leaf packing requires `TREEDB_ENABLE_LEAF_GENERATION_PACK_MAINTENANCE`, outer leaves, and quiet/admitted work; it is skipped on GC ticks. Defaults bound a pass to 256 MiB copied and 32 generations, require at least two candidates and one commit of age, use a 30-second interval/timeout, and require 250,000 ppm reclaim per copied byte ([opt-in and admission](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:31147), [defaults](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:2432)). Automatic post-rewrite generation vacuum returns early; public background index vacuum is a separate mechanism with a default 30-second interval and platform/admission gates ([post-rewrite path](/private/tmp/gomap-qs-5005-verify/TreeDB/caching/db.go:23900), [public vacuum](/private/tmp/gomap-qs-5005-verify/TreeDB/public.go:1233)). Maintaining small disk usage requires enough eligible opportunities and effective recovery-horizon advance; scheduler presence alone proves neither.

## Method review

The updated graph-owned [maintenance.py](/Users/michaelseiler/dev/snissn/gomap/tmp/quicksilver-space-memory-20261005/maintenance.py:59) records `final-before-verify`, `before-maintenance`, and each `MODE-before-oracle` / `MODE-after` census. Use the first label for retained post-workload footprint; the second for the input after the initial verification reopen; `MODE-before-oracle` for compactor footprint after its process closes; and `MODE-after` for verified public reopen/close footprint. Report the oracle delta separately, including dictionary, outer-leaf, user-value, index, metadata, apparent and allocated totals. Do not substitute the main-backend compactor byte report for the whole-directory census.

The oracle uses the ordinary writable DB factory and closes the resulting handle, so it is not representation-neutral. Public open/close may persist metadata, create/clean WAL, replay recovery, or invoke inherited close/background maintenance ([oracle](/private/tmp/gomap-qs-5005-verify/cmd/unified_bench/suite_quicksilver.go:987), [ordinary public open](/private/tmp/gomap-qs-5005-verify/cmd/unified_bench/adapter_treedb.go:1072), [close maintenance](/private/tmp/gomap-qs-5005-verify/TreeDB/public.go:1728)). Historical rehearsal census cannot retrospectively separate these effects.

The timeout starts a dedicated process group, records failure, and refuses normal reopening after timeout/failure. It bounds the owned command rather than unrelated native work. Completion/reaping of the leader is not a universal proof that every possible descendant has exited; the known command topology should remain bounded and owned.

[observe.py](/Users/michaelseiler/dev/snissn/gomap/tmp/quicksilver-space-memory-20261005/observe.py:12) traverses descendants of the owned producer and samples matching unified-bench processes every 0.5 seconds. VmHWM preserves the process's total-RSS high-water mark once observed. RssAnon/RssFile/RssShmem are sampled components, not kernel component high-water marks; retain the actual co-time snapshot and never sum independent maxima as a measured simultaneous peak. Traversal reads each leader thread's children, so arbitrary forks from other threads can be missed. Very short process lifetimes or final intervals can also be missed. This is a process-memory diagnostic, not a kernel cgroup peak or an aggregate memory proof.

## Ranked safe next work

1. **Prove a productive maintenance finalization boundary.** Highest likely disk benefit per change: on an isolated leaf-pack fixture, compare checkpoint-only settling with a supported unchanged-logical-state durable successor, then GC. Reuse [the leaf-pack horizon test helper](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_pack_test.go:40) and [reopen/GC removal coverage](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_pack_test.go:542). Acceptance: lower whole-directory bytes without another live-data repack; every recovery-selectable root, pinned snapshot and registered protected root remains readable; reopen/miss oracle and crash/older-slot tests pass; bounded allocation and peak memory. The helper's ForceCommit is a test technique: command-WAL rejects unlogged manual root publication ([guard](/private/tmp/gomap-qs-5005-verify/TreeDB/db/command_wal_raw.go:1100)). Do not copy the system-root horizon helper, which deliberately replaces system-root contents. A production successor mechanism is a causal followup, not authorized or proved by this report.

2. **Separate retained and actionable audit debt, then avoid ineffective settling.** Lowest-risk diagnostic/CPU-memory candidate: make recovery-retained bytes explicit alongside currently reclaimable bytes; preserve existing conservative completion flags. Only stop redundant settling when no other phase, publication or resource-release event can make progress. Acceptance: retained sources are still protected and reported; final state/bytes match the existing flow on pinned and older-recoverable fixtures; fewer scans/allocations are measured on the zero-eligible case; no changed deletion authority. This could improve maintenance cost, but cannot itself promise less disk.

3. **Qualify existing bounded automatic leaf maintenance before changing defaults.** Test the current opt-in policy under a retained churn workload with production background maintenance enabled, sufficient quiet opportunities, and memory/latency capture. Acceptance: storage growth reaches an explainable steady range across several cycles, eligible debt drains, retained debt tracks actual roots/pins, tail latency stays within the agreed budget, and maintenance memory remains bounded. Prefer policy/integration evidence to a scheduler redesign. No unconditional default flip or algorithmic rewrite follows from the disabled-background rehearsal.

No-go for now: skipping every zero-dead candidate in CompactStorageExhaustive or changing shared manual Force semantics. Packing applies current codec/dictionary and groups decoded leaf pages, so zero dead bytes can still allow recompression or consolidation gains ([pack encoding](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_pack.go:310), [grouped-page byte accounting](/private/tmp/gomap-qs-5005-verify/TreeDB/db/leaf_generation_pack_rewrite.go:637)). The equal-sized singleton proves a local useless repack, not a general rule. A future CompactStorage-only repeated-identical-packed-singleton guard needs reliable provenance/policy equivalence plus singleton, multi-generation, changed-dictionary and changed-grouping counterexamples before it is a safe optimization.

## Outstanding uncertainty
