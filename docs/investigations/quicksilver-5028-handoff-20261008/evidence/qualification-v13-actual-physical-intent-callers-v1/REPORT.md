## Narrow all-current-path protocol and preserved failure boundary

Detach only before the no-I/O assigned-validation/publication cut: keep tracked private output, exact frozen producer tokens, base pins/index/runtime and semantic manifest inputs; release actual root locks/gates; conditionally prepare the exact immutable manifest and any required producer waits; reacquire original serialization order and validate base/index/root/CommitSeq/manifest/pending coverage. This still requires the serialized tracker/clone and group finalizing owner described by the prior repair design.

For nil/assigned physical or group intent, do **not** unlock again merely for appendRawKVCommandWALIntent: its current fast branch is safe under these locks. On exact basis drift discovered before entering that validation/finalizer cut, abandon only unaccepted private output; preserve the existing captured-prefix owner and return/retry through its existing basis-mismatch contract. Optimistic already rejects root/sequence mismatch and frees tracked output before the append cut (`batch.go:552–565`). Serialized gets the corresponding check through the proposed tracked detached-attempt refactor; group must return a whole-group unaccepted basis error, retain the cache prefix/cut, and never internally replay closed member batches or rebase a changed user tree. A later WAL append alone may coexist with the fixed cached prefix; it does not authorize expanding that prefix or replacing a changed backend root.

After that cut, retain all existing error semantics. Group marks commandAppended=true even for an assigned validation return (`root_publication_build_group.go:401–408`) and poisons on unaccepted subsequent failure (`:458`); serialized does so at `batch.go:870`, optimistic at `:623`. Do not treat those assigned errors as harmless preassignment retries. Preserve post.accepted/Accepted() on accepted-wait errors and never free accepted output. Contiguous ranges, poison checks, applied-LSN visibility, both exact durable slots, CRC, late fences and required ACK waits remain unchanged.

Ordinary genuinely unassigned intents are the other branch: they originate inside nonphysical Batch.write's retained `LockCommandWALPublishWithBarriers` guard. Their dependency/journal sync remains outside root locks; revalidate afterward, and any assigned-but-unaccepted drift/error retains existing poison/recovery. No generic borrowed guard is needed for the current physical/group call graph because it does not enter this branch.

**Conclusion:** the stronger admission-borrow API is unnecessary for the actual current repair scope. Keep a fail-closed invariant that physical/group inputs remain nil or Set-produced assigned non-replay records; refuse an unsupported future unassigned/replay/prefix-group input rather than accidentally synchronizing under locks.
