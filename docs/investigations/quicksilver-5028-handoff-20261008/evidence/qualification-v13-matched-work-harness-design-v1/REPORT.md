## Receipt and telemetry seam

An additive `matched_work` object on the concurrent phase should declare schema, mode, allocation_scope='process_go_runtime_full_composition', requested/completed_reads, writer mutation targets, completed_groups, successful_commits, completed_checkpoints, reader_joined, writer_joined, completed, reader_elapsed_ns and both_join_elapsed_ns. Include reader_cut and both_join TotalAlloc/Mallocs deltas, HeapAlloc/NumGC/PauseTotalNs support, and explicit successful-work denominators. Both-join acceptance requires exactly6M/40000/40/160/4, correct requested-present+absent sum, no error/cancel/close failure, and both joins. These are process-wide Go allocations, not exclusive read/write costs or native allocator/RSS measurements. Report total bytes/mallocs and normalize by reads and mutation targets with BOTH denominators explicit; do not sum unlike records into an unexplained per-operation unit.

Cut telemetry must be synchronized rather than read concurrently from res slices. Use a preallocated scalar writer progress record, updated at existing successful group/commit/checkpoint boundaries; no per-read synchronization. Sample the progress record immediately before and after the reader MemStats call, retaining both sample timestamps/statuses. Equal bracketing counts prove an unchanged completion count during the cut; differing counts mean an interval, not an invented exact instant. The full composition counts are exact after writerDone. An in-flight checkpoint may have started but not completed; report that state separately. Retain partial successful counts and error text on failure as diagnostics, completed=false, never eligible numerical evidence. A reader finishing early must not cancel the writer. Existing cancellation on errors still drains/joins both sides before DB teardown.

CPU profile stops at reader join today, while the allocs pprof after-snapshot is written after the entire phase returns (`suite_quicksilver.go:677–721`), including writer tail and merge/report allocations. These boundaries are distinct. For fixed-work only, delay CPU stop until both-join cut; retain original filenames/phase list in separate run directories, and bind config mode plus profile-scope metadata. Allocation pprof remains diagnostic support with its broader endpoint, not a substitute for MemStats counts. Update profiling docs and existing artifact tests if reported contracts change; avoid a second suite or duplicate writer.
