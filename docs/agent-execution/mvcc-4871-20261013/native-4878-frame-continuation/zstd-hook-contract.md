## Records versus bytes under the EXISTING work contract

Use a caller-provided reserve callback mapped directly to iterator.OrdinalScanWork.Reserve, not a fork-local alternate budget or record cap. Ordinary fixed scalar arithmetic does not create a physical record visit. Bounded contiguous copy/clear/hash work can reserve a chunk record plus all actual read/write bytes; it still must pause at available byte budget.

Independently interpreted source/entropy-token/table/sequence probes consume record work before each visit. A sequence performs LL/ML/OF table-source probes and bitstream actions, then copy work; count those actual source actions rather than declaring the entire block one record. Table construction must retain partial entry/symbol progress and charge the actual visited/read/written entries. Huffman literal decoding must expose actual entropy/source progress and output-copy bytes; it cannot waive 2048 table probes because the table is fixed. Exact reservation granularity must be mapped to the already-required native definition in the implementation and tests; this proposal does not create or relax a gate.

The 128KiB input/output size alone can fit a byte component while arbitrarily many of the 98047 sequence visits exceed 32 records. Header/skippable transitions, 512/2048 table work, dictionary parsing and history preparation are independent costs. One explicit block API with unchanged hidden helpers is insufficient.

A minimal proposed extension is an owned Begin/Step/Cancel continuation on the existing Decoder/frameDec/blockDec/history/entropy types. Begin captures original bindings/admitted storage only and must not call Reset's fast DecodeAll path. Step exposes the phases above, stores original state after each accepted action and refuses before unsupported effects. Cancel prices original retained backing/pool/alias release without inventing a manager or physical refund. Keep NewReader/Reset/DecodeAll and their ordinary fast paths unchanged; add a bounded mode factoring the original generic logic. Caller-owned storage can avoid eager constructor preparation, but actual containing admission and dictionary/history lifetime must be proven. No duplicate ZSTD codec is proposed.
