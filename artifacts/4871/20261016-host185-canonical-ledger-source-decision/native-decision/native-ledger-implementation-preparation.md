## Recommended mutation-safe traversal: pin original descriptors, no moving markers

The literal moving-marker sketch can livelock: `M1,M2,burn → M2,M1,burn → M1,M2,burn`. Do not implement that swap rule. Use the root-permitted exact pinned original node alternative instead:

* At successful burnable tail claim, before the first possible write, assign the checked monotonic identity AND append the original reservation-embedded descriptor to the SAME canonical descriptor list. List membership starts non-burned; failure changes its disposition to burned without allocation. Assign/link occur together under ledger.mu, so identity order is list order even when failures complete out of order. The original candidate tail exclusion still governs non-burned descriptors. This is one canonical representation, not a parallel list of copied intervals.
* Logical commit captures `stopID=latest linked descriptor ID` in its original seal child. The child pins one current original descriptor, with a pin count in that same charged frame. Immutable descriptor ID/range are never reused. At first progress it selects the first node under ledger.mu; if absent or ID>stopID, the scan is done. A descriptor linked later has greater ID and is excluded from this receipt's scan even if its write fails immediately.
* Physical unlink/refund is forbidden while a scan pin exists. A logically removed descriptor is a tombstone that stays in its original list position/charge until the last pin leaves; current.next is therefore read safely under ledger.mu on the next call. There is no saved peer-marker pointer and no peer containing-seal borrow. Receipts do not insert traversal markers at all.
* Each invocation admits the actual current descriptor visit/comparison before reading it. For a burned node, persist one immutable coverage index; revalidate burned/tombstone state under ledger.mu before removing its exclusion. If another receipt removed it, advance conservatively. Pending/non-burned nodes are skipped; if one burns after this receipt passes, its exclusion remains for a later publication. No coverage claim can authorize a future burn merely because its identity is old.
* To advance, under ledger.mu admit the fixed relink/pin work, pin next (only if ID<=stopID), detach the old pin, and save the new current node before unlocking. If the old pin was the last edge of a tombstone, clear all actual descriptor/frame aliases and transfer only owner+charge into the surviving seal's embedded RemovalWork. Drain that scalar debt before another advance. At most one pinned node and one scalar accounting debt exist per receipt. No recursive next-pointer ownership or retained peer history is created.
* Reservation map/candidate/seal operands are separate original edges: tombstone is reclaimable only after its canonical candidate entry and its exact seal/producer aliases have also detached. Clearing the candidate entry is not enough while another scan holds its frame. A failed reservation's vectors must be scrubbed/refunded by its real cleanup before the frame can become a burn-only node; if that cleanup yields, the same original reservation/caller retains it.

The progress measure is `(remaining original descriptor identities <= stopID, remaining coverage operands for current ID, original RemovalWork phase)`. Traversal identities strictly increase; no peer can move a node back into this receipt's prefix. Finite new writers only add identities beyond stop; other removers only remove exclusions or shorten the remaining traversal. Original owner shrink progress remains its own documented condition. Total historical traversal is still finite work, not a one-turn or whole-memory bound. Pending tombstones remain individually charged; they are not silently refunded or claimed absent.

This requires selected source changes for descriptor pin/last-alias custody, but no new owner, registry, receipt, or borrowed peer-frame lifetime protocol. It is the recommended concrete traversal representation for the next source batch, replacing the conditional marker option. Discriminating controls must alternate two receipts at every step, remove the other's pinned current node, append/fail after stop, and assert exact pin/charge endpoints.

## First remaining representation choice: actual original map backing

`owners map[uint64]CandidateIDV1` and `candidates map[CandidateIDV1]*reservation` currently have neither retained Owner admission nor source-visible capacity/backing. `claimStorageBoundLockedV1` is a work-traffic bound, not a retained heap bound. Exact header/vector admission does not cover these tables. Root's new requirement to admit map storage through the same owner cannot be met by a guessed scalar or unsafe runtime layout mirror.

Strict complete-retention route, if selected: replace these SAME two canonical fields with capacity-known typed tables whose actual arrays are admitted through the same owner, with explicit original probe/growth/refund continuations. All ordinary/native consumers must switch together; never keep a parallel authoritative Go map. This extends the representation scope beyond stable burned nodes and requires a deliberate root choice. The alternative is an explicitly accepted original canonical Go-GC map domain, with no aggregate retained-heap claim; that is an accounting contract choice, not something this plan assumes. No new registry/owner is needed for either option.
