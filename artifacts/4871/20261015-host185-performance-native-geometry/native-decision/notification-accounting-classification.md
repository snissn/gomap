## What can be priced without inventing an owner

Root's existing pinned Go1.26.3 ELF evidence (`native-build/runtime-layout-evidence/dwarf-types.json`, `go-version-m.txt`) supplies layout sizes, not allocation-lifetime receipts or universal constants. At the unchanged actual source sites:

* One unbuffered changed-channel creation requests112 header bytes through `runtime.makechan`; count its close/create operations and actual assignment/access traffic separately. It has no element backing. Retainedalloc's rounded allocation charge is not a refund entitlement for this GC-managed service output.
* One `time.NewTimer` creates a cap1 `chan time.Time` and one runtime `timeTimer`. With this pinned source and pointer-bearing time.Time, these are separate112-byte header,24-byte element backing and112-byte timeTimer requests:248 raw requested bytes across three allocations, before any separately stated rounding convention. The public16-byte time.Timer is already the runtime object's prefix; the96-byte runtime.timer is embedded, so neither is added again. Actual `realTimer` interface representation/escape must be established from compiler evidence before asserting an additional wrapper allocation or its absence.
* Real clock reads, timer channel access, Stop, wake select and notification operations remain charged actual work. Global runtime scheduling internals and arbitrary goroutine wake latency are not claimed to have a complete transitive heap or latency bound. `close` may service actual wait queues: no-observer/scheduler geometry must be validated or bounded before a complete operation forecast, rather than claiming the header size bounds close work.

The diagnostic can record cumulative allocation/work traffic, including service allocations that remain reachable later. It must not subtract them at replacement, terminal receipt completion or Finish. That traffic sum is neither the live retained PRIMARY quota nor a deterministic GC reclamation claim. If the final envelope uses a rounded service-allocation convention, state it separately from real retainedalloc ownership; do not call source layout bytes exact transitive Go heap consumption.

The old alias examples remain true: the four original changed-channel consumers copy a local channel outside c.mu, and the scheduler copies timer.C. The newest changed channel remains in the SAME coordinator even after terminal native completion. These facts reject early native-owner refund, but **do not force a registry when no such owner/refund claim is made**. Introducing a registry would expand scope and ordinary behavior without being necessary for this accounting boundary.
