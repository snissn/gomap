## Smallest concrete representation

Use one explicitly sized `[]uint64` slot array, power-of-two capacity, with empty slot zero **and a separate embedded `zeroPresent` bit**. Key zero is a full supported member represented by that bit, never silently excluded or confused with absence. Count nonzero slots separately from total membership (nonzero count plus the zero bit); occupancy/load uses the nonzero count. Empty/key-zero-only sets can have nil backing and zero array charge. The distinction must be reflected in all length/presence observers. This avoids both a second occupancy allocation and the padding cost of a `{uint64,bool}` cell. No tombstones or per-key deletion are needed for these append-only private sets; final reset consumes the whole set.

Embed owner pointer, current array/charge, counts/version, in-flight replacement array/charge and original finite mutation/removal state in the already owned preparation/planner storage. Keep exact typed views bound to the actual private transaction/sink; nil private view continues the original ordinary map path. Do not add a map+table shadow, a new Owner, a keeper registry, a pool, a new arena or a general exported table package. Use the existing admission/typed-removal mechanism for explicitly sized backing arrays; this is the same private scratch domain already used by reservation normalization. Persistent root-bank arenas have a different lifetime and authority contract. Importing rootpublication's registry table into freelist would also create the existing dependency cycle; reuse its growth/accounting discipline, not its authority type or unbounded methods.

Use a fixed, full-width uint64 avalanche mix and linear probing; account the fixed hash operations and each actual inspected cell. A raw low-bit identity hash is a poor choice for structured chunk/page IDs. Keep occupied nonzero load at most one half, with checked initial capacity (the existing maintained table starts at 16) and geometric doubling. Check all integer/capacity/multiplication/charge overflow before admission. Bound a probe by capacity; failure to find an empty slot under the maintained load invariant is corruption/error, not an infinite loop. An explicit observed key/version/array/cursor binding prevents a paused operation from being resumed against a different set or key.

Under well-distributed hashes, membership and insertion are expected O(1), n inserts and geometric rehashing expected O(n). Enumeration costs O(capacity), which is O(n) at the maintained load envelope except the constant minimum capacity. A deterministic mix does **not** establish an adversarial constant bound: a probe can cost O(n), pathological rehash/build O(n²). Retain every collision/probe continuation and report actual work; never precharge all possible probes as one unpriced or oversized hidden call. This recommendation removes unconditional slice quadratic work, not worst-case hash collisions, and makes no measured public latency claim. If a worst-case logarithmic algorithm is an explicit requirement, this table alone does not satisfy it; do not silently infer such a requirement or claim.

For capacity C, array backing charge is exactly the existing policy `Q(C * unsafe.Sizeof(uint64(0)))`, where Q is `retainedalloc.AllocationCharge`. Header/cursors/embedded RemovalWork are charged in their actual containing allocation, not again per key. At C=16 the raw array is 128 bytes before Q; compare that honestly with a tiny slice, which can be smaller. With power-of-two capacity and half load, array bytes are roughly 16–32 per nonzero key, versus 8 per retained slice key, plus conservative Q rounding. The table trades some capacity and initial constants for expected scalable lookup; it is not a demonstrated tiny-fixture allocation improvement. Key-zero state adds no separate backing allocation.

## Finite construction and growth

Each original insertion has explicit phases: bind/probe; growth admission if needed; allocate; rehash; final insert/swap; release obsolete backing debt. Admit the fixed hash/header traffic, each cell read/write, allocation/zeroing and every loop visit before performing it. Preserve a discovered duplicate or insertion location only while the same key, table version and backing remain bound. No lock, live map iterator, cell pointer or unused permission survives a return.

Before `make`, use checked explicit capacity, reserve its actual allocation/zeroing plus header effects and call `retainedalloc.AddPendingWithOrdinalWork` on the SAME owner for the **entire new Q(Cnew*8)** while old Q remains charged. Allocation follows successful admission in the same invocation; never reserve work now and allocate on a later call without fresh work. A refused Add has no new backing/admission effect; retain the ready/error distinction, including strict unsupported-lease errors. No nil-work fallback in selected native mode. Allocation is an indivisible source operation: if its zeroing/allocation unit exceeds a fresh 1MiB vector, return the original explicit unit-too-large/pre-effect refusal. This is a representation limit to report, not a cardinality cap derived from 33/80/4096 or a useful-progress proof. Do not introduce a segmented allocator merely to hide that boundary in this small batch; segmented capacity would require a separate explicit design if later necessary.

Rehash old cells incrementally into the private destination. Save source index, current key, destination probe index and exact growth phase so collision work resumes rather than restarts. Freeze mutations/enumeration of this private set until that operation completes; ordinary writers remain free to mutate their distinct canonical maps. During growth, old and new arrays are both physically live and fully charged: peak is `Q(Cold*8)+Q(Cnew*8)`, not Q of their sum and not only the final table. A geometric doubling is approximately three old array capacities before rounding.

The source/current table remains authoritative until destination construction and the pending key can commit. Then reserve the swap/count/version/insert effects, detach every old alias (growth source, cached iterator/view/cell handles included), and only then drive the old charge through an embedded original `RemovePendingWork`. A scalar refund debt after physical detachment is still charged accounting debt, not another physical array. Do not start another growth or reset/reuse its removal state until complete. `ResetCompletedWork` is the existing checked reuse seam; do not copy an active RemovalWork/mutex or erase a pending receipt via a whole-struct assignment. If post-commit removal yields, resume the committed phase without reinserting the key. Sink duplicate detection must distinguish a new duplicate (`ErrGenerationFormat`) from resuming its own committed insertion after later work refusal.

Replacing its O(n) copy reservation with n supposedly constant table inserts can hide collision loops inside that lock. The narrow safe route is an exact admitted snapshot vector of uint64 IDs under that same lock, then incremental private-table construction from the immutable vector after unlock. Admit/charge the whole vector on the SAME owner before allocation, price every map visit/copy, and never retain a live map iterator across unlock.
