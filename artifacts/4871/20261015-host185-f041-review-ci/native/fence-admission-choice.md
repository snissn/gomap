# Native pre-fence ledger admission: source-backed choice (not yet implemented)

The ordinary `rootPublicationRuntimeV1.Publish` contract explicitly holds no DB write/commit/root-build/preparation lock over `executeDurableRootStorageTransactionV1`. Keep that path unchanged. The accepted `live-startup/native-split.md` requires no admission Cut across a wait, admission committed at actual visibility, and publication turn released before delayed physical Finish; it does not explicitly authorize changing I/O lock concurrency. The narrow native lock scope below therefore requires the coordinator's explicit policy choice.

## Why a captured scalar bound is insufficient for the current core

`freelist/generation_v1_reservation.go:publishBatchLockedV1` traverses each selected reservation's immutable ids, but also the current complete `burnedTails` vector for each abandoned-coverage vector. `RollbackPreVisible`, `Fail` and the retained rollback engine can append burned tails from independent private preparations under the ledger mutex without allocator.mu. A selected activated candidate has immutable ids/coverage (`reserveTailLockedV1` rejects state other than PreVisible), but that fact does not bound the live burned vector. Another private candidate may have reserved a tail before selected preparation and fail later; selected skipped-prefix coverage may cover that newly burned tail. Thus preadmitting the old vector length and invoking the unmodified complete publisher later understates actual work. Checking again after fsync can refuse only after authority was installed. Locking allocator alone does not exclude those ledger mutations.

This is not an impossibility result for all immutable schemes. A canonical persistent burned-tail representation or an admitted exact mutation plan plus appropriate reclamation semantics could preserve unlocked I/O. Both require changing the ledger representation/publication algorithm, not merely holding an immutable prefix. Leaving covered burned tails forever is an accumulating reservation leak; moving original ledger mutation into Finish delegates mutable authority across a newer writer and is rejected.

## Narrow scope proposed

Run dependency flush/sync, manifest/index materialization, namespace stabilization and stable index sync with the existing unlocked path. Only immediately before `WritePrimaryCapsuleWithFenceV6`:

1. Acquire durablePublishMu, rootReuseMu, runtime.mu, allocator.mu, ledger.mu in that order. Validate SAME active seal/member/debt/prefix and current durable base. Admit all actual runtime debt/seal compactions and original allocator+ledger geometry, and reserve actual pager authority work before any authority write.
2. Release runtime.mu before callbacks/I/O; keep durablePublishMu/rootReuseMu and allocator/ledger locks until the actual authority write and nonfallible original ledger/install commit. Commit helper must skip acquiring those locks and call original canonical ledger policy with ledger already held. Reacquire runtime.mu only in the same outer DB serialization scope; no path holding runtime.mu may wait for this allocator scope. Better hold runtime.mu through the fixed authority write only if source review proves every hook cannot reenter it; avoid that stronger option.
3. Release all scope locks before original Consume/ReleaseTurn can return or any Finish pause. Every refusal before authority unwinds scope. Every ambiguous write releases scope before failure disposition. No scope/control survives a yield or a public call.

Actual allocator work: prefix validation and ID build; seen map validation; ids owner deletion; each burned interval against each actual abandoned interval plus kept-vector writes; candidate deletion; published marking; activated-vector copy/clear. Conservative admission should use >=8*prefix + activated + sum(ids) + sum(burned*(2+coverage)) records, and actual operand bytes plus explicit conservative map work bytes. It is an execution bound, not exact Go-map heap admission. Runtime commit includes prefix/debt validation, debt copy/clear, seal partition/clear and fixed two-slot ownership transfer. The pager authority entry itself reserves 5 records plus 2 real-file fence records (and one forwarding record for primary-bank namespace), 2*3*pageSize+1024+4096 bytes; retain those actual reservations rather than calling it with nil. No Q32 viability is claimed; the complete single-call window may still refuse.

## Remaining lock risks before implementation

`writeOwnedSpanWithWork` holds the PRIMARY pager mutex while running synchronous durabilitycut observers and beforeFence. Production callbacks only inspect ctx/failpoints and emit stable-handle events; `WithPinnedFile` calls directly without a token lock. A test observer that synchronously calls a writer would deadlock on the proposed DB locks (and on same-pager reentry today); integrated observers must signal an external goroutine and return, never wait for a writer until Finish is paused. Namespace stabilization is outside this scope. DATA allocator paths acquire allocator then DATA pager; authority uses a separate PRIMARY pager. No production pager->allocator callback is present in this authority call. Need verify all runtime.mu->allocator sites against the proposed reacquire: releasing runtime.mu while keeping allocator is unsafe if any runtime-only caller can acquire runtime and then wait for allocator. Holding runtime through authority instead removes that inversion but requires excluding reentrant observers. This is a real choice, not silently settled here.

Close first sets closing under maintenanceMu, crosses writeMu, then calls JoinNativePublicationsV6 outside teardown/publication locks. Stop joins before coordinator stop. Original cancellation must execute only after scope unwinds; it may acquire allocator/ledger normally. There must be no call to owner.Close or failed-receipt disposal under the scope.

No source change implementing this native scope has been made. Existing standalone `PublishActivatedCOWPrefixWithWorkV6` remains pre-effect safe but cannot be used after the actual fence as a work-admission substitute. Q32 RED / ACK0.
