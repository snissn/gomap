Select the following connected protocol.

1. Add one fixed operation slot to the existing registry header. It contains kind/stage, an originating admitted continuation identity, current node/parent, candidate handle/branch bit, and a conservative pre-mutation slow minimum. The continuation lives in the original Snapshot/runtime/source constructor or disposal parent, not a newly allocated work object. Add distinct guard kind and role-reference count to the canonical leaf. All registry operation fields and saved tree pointers are protected by `registry.mu`; no saved path array or new collection is needed. Charge actual enlarged containing headers and separate leaf/branch allocations before birth.
2. Only native structural operations can leave this slot unfinished across unlock. Ordinary slow-tree insert/remove/first-hole/summary-dependent callers complete an active operation with explicitly accounted helper steps before performing their own structural mutation, under the same registry exclusion. They never wait for the native caller to return. Fast cohort operations and minimum reads do not help. Native calls advance the same engine themselves when no helpers arrive. Ordinary operations finish their own structural mutation before unlocking, as today; they cannot perpetually install a new paused operation ahead of a waiting native caller.
3. Native insertion stages are: admitted allocation; install operation; first-hole search; original leaf descent; original insertion-point descent; initialize/splice; repair one ancestor; finish. Save the actual current node after every charged step. All other slow-tree mutations first help this operation, so no cursor node can be removed or reused while saved. At depth63, each of the three search passes and the final ancestor pass is finite, with at most 63/63/63/64 visits respectively; this is a structural bound, not a reader-count cap. Header entry, terminal root-leaf cases and sentinel transitions are separate charged steps. No global version retry occurs.
4. Known-leaf last drop stages are: validate exact registry/leaf/guard kind and original counted edge; mark withdrawing; atomic constant splice; repair one ancestor; terminal detach. Last drop forbids new guard borrows under the same mutex. Ordinary Unregister must reject guard-kind leaves even if a positive handle is reused; it cannot withdraw a source guard. Do not hand a pointer token to a caller without an actual counted edge. Clear tree/cursor/temporary aliases before returning only `(same Owner, exact charge)` to the original disposing parent. The independently allocated branch may be removed with a different leaf later: preserve its same metadata Owner charge, as current `detachLeafLocked` does.
5. Queries during a pending mutation use `min(fast-min, pendingSlowFloor)`, without trusting half-repaired slow summaries. Set pendingSlowFloor before the first splice to the old exact slow minimum, additionally min with the new leaf sequence on insertion. Old floor is conservative after deletion; min(old,new) is conservative during insertion. It is valid even for sequence0. Tree handle/count/range consumers finish the pending operation before using those fields. Clear the pending floor only after the new root summary is exact. Parent-source overlap protects capture until child guard enrollment and exposure; it is not a substitute for finishing the operation. Renew an immutable floor by inserting the genuine new guard, transferring real roles, then dropping the old guard. With no real old readers left, finite completion removes its old minimum; there is no permanent ancestral floor.

This admits a bounded, conservative intermediate minimum and an exact completed minimum. If the contract instead requires the exact instantaneous slow minimum after every splice, the proposed deferred repair is ineligible: that is the precise contract decision. The request permits conservative intermediate minima with eventual exact renewal. It does not permit a stale floor after completed last-drop/renewal.
