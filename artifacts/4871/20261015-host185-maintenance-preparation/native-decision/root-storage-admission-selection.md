# Native storage admission: selected source construction, no runtime grant

Root selects the following coherent continuation of the existing native source batch. The supported publication allowance and complete retained-byte/Finish totals remain unproved. Original Q32/1MiB, fixtures and ACK0 refusal remain unchanged. This is not a new numeric allowance, public activation, native publication experiment, portability waiver or graph completion.

The remaining mutable storage costs are real: native page writes currently retry verified-word CAS, and captured index sync traverses the live dirty bitmap/count/worker geometry after adoption. Concurrent ordinary operations can change those terms. A preactivation snapshot is insufficient. The allocator's existing physical-tail validator already permits a newer activated/in-progress tail; no tail-validator bypass is selected.

The selected representation keeps the same original objects and physical order:

1. Explicit native mode in the existing candidate-page and typed-capsule write cores conservatively clears the original verified word with one atomic store. It never manufactures a verified bit. The ordinary masked-CAS path remains. Native writes may evict adjacent checksum-cache hits, causing later real verification work; that cost must be disclosed and eventually measured. Target-page immutability/reuse invariants remain mandatory.
2. On Linux, the original native captured pager callback fences its same retained file descriptor under the existing pager read lock. It does not inspect, detach, clear or restore any dirty membership. The existing file fence covers mapped writes; preserving bookkeeping can leave work for a later ordinary sync and is not a zero-cost claim. Materialize, PRIMARY token sync and namespace stabilization, DATA token sync, then capsule authority retain their original order. Value-log/external-resource and namespace obligations are not replaced by an index file fence.
3. Both native captured-index sync and typed capsule use one direct `Fdatasync` attempt plus `KeepAlive`, without repository-owned EINTR retry or fsync fallback. Use a single `Fstat` into charged stack storage for actual extent if needed. This explicitly narrows native availability; ordinary retry/fallback behavior remains intact. Real physical errors, including EINTR/ENOSYS/EINVAL, retain the original sticky first-error/custody graph. A pre-authority failure is known-unfenced; failure after capsule copy remains potentially durable/ambiguous. No ACK, refund, completion or successful teardown follows from either error. Kernel execution duration/internal work is not a product byte-copy bound.
4. Required capability/platform/shape and full storage/Consume/completion-plan checks occur before activation. Platforms requiring mapped-range flush refuse before activation until an actual bounded dependency-range closure exists. Budget, stale, cancellation and unsupported-shape refusals must never be relabeled physical errors.
5. Atomic enqueue and start of the same admitted attempt share the existing coordinator mutex. No ordinary-enqueue gate, whole-publication lock, second owner, guardian reference, registry, scheduler or callback debt is added. Actual Set release stays in the same physical Finish, and later ordinary publication must progress while that Finish remains paused.

Worker may implement this coherent batch and use compiler, pure controls and bounded focused pager primitive unit tests, including actual primitive descriptor sync. Every run requires exact source manifests and timeout/kill/join receipts. No native DB activation/fence/final-driver execution is authorized. Root and independent review must inspect the resulting complete F/Finish/disjoint retained ledger and every error branch before selecting any finite diagnostic allowance.

The independent storage advice is design advice, not acceptance of the mutable implementation. Full original final gates remain open, including supported total work, retention, physical Finish/Close, newer durable writer, old reader/reopen, public cost, platform behavior, exact-head CI/review and graph qualification.
