The prior permitted previsibility run passed with all 10,330 source hashes equal before/after: `native-build/atomic-completion-source/previsibility-prefix-growth/{source-before.json,source-after.json,result.json,run.log}`. ## Recommendation

Implement both narrow alternatives on the native work-bearing route, with a single-attempt Linux file fence shared by native index synchronization and the native typed capsule fence. Keep ordinary masked invalidation, dirty snapshot synchronization, retry/fallback, and ordinary capsule behavior unchanged. Reject unsupported platforms/observer modes before activation. This removes two genuinely variable source loops; it does not establish the complete final-turn bound or public progress.

### A: checksum-cache word invalidation

`pager/write_work.go:writeViewWithWork` and `writeOwnedSpanWithEffectWorkV6` currently reserve additional work on every failed verified-word CAS. On the finite native route use one `atomic.StoreUint64(word, 0)` after the same mapping/bitmap geometry validation and before dirty marking/page copy. Keep the ordinary nil-work masked CAS path. The owned span already requires all two/three pages in one verified word.

`pager.go:IsVerified` only reads the page's bit. The seven production callsites in `tree/tree.go`, `tree/inplace_update.go`, `db/maintenance_reachability.go`, `db/leaf_generation_pack_rewrite.go`, and `db/db.go` all treat false as a reason to verify the actual checksum. `MarkVerified` only sets bits after verification. Clearing an adjacent bit cannot manufacture positive verification or change root/page/resource ownership. A concurrent setter either precedes the store and loses its cache entry, or follows it and records verification again. Existing exclusion against rewriting a page being read remains required, exactly as with the old masked invalidation; this is not new permission for mutable reads.

Moved work: at most 63 adjacent cached pages per one-page write, or 61 for the three-page capsule, may need a later ordinary checksum verification. Repeated native writes can cause repeated cache misses. Report this cross-reader cost; do not claim aggregate reader latency is bounded by the native invocation. No new storage or retained aliases. Count the actual one atomic word store and its 8-byte traffic in the write's pre-effect formula; remove retry-dependent pricing only because the retry no longer exists. Atomic AND is not an adequate substitution where its implementation retries.

### B: Linux exact retained-file data barrier

The original Linux policy (`pager/mmap_sync_policy_linux.go`) deliberately uses the file data barrier to fence mapped writes. `syncDirtyChunksWithFileWork` nevertheless detaches dirty ordinals, scans its bitmap, allocates the snapshot, and prices restoration/worker paths. Those are unnecessary to establish the Linux whole-file durability fence. The existing capsule core already deliberately preserves all dirty membership after its file barrier.

For the exact native stable-pager callback, retain `operations.pager`, `token.pinned`, original token identity, original Snapshot, and the original callback/Set lifetime. Under the original pager `p.mu.RLock`, execute one file barrier against that SAME pinned descriptor; preserve dirty words/count/hints untouched. Do not reopen a path, reuse an earlier fence, or replace the token. `syncPath` remains diagnostic only. Original token construction already binds the retained descriptor identity; pointer equality with `p.file` would incorrectly reject its duplicate descriptor.

Ordinary writes/growth using `p.mu.Lock` cannot race mapping teardown during this short pager I/O scope; this is the same read-lock shape already used by the original sync. Do not hold this pager lock across the whole publication. The retained descriptor also continues to supply authority after pager retirement as required by the existing stable-file API; a closed mapping does not invalidate its still-owned file descriptor. Current-index/final-basis validation remains a separate original transaction obligation.

No dirty state is detached, so failure needs no dirty restoration. Later ordinary sync can redundantly fence and clear the preserved entries. Borrowed mutable mappings can become dirty again after the barrier; no membership is lost. Retention is the existing dirty directory, with no new list, goroutine, backing, owner or deferred native callback. This is not a sustained-memory qualification claim.

The actual PRIMARY token and DATA token both still execute their genuine file fences, original wrapper clock/metric operations, and stable namespace checks. The external dependency Set's original empty Flush/Sync validation still executes. The capsule is written and fenced afterward, with its original mutation flag, fault guard, final authority scope, and original post-fence commit. The native pending candidate/receipt and Set edge remain intact until their selected success/error and true Finish paths consume them. Preserving dirty bookkeeping cannot replace any of these edges or reorder publication.

## Remove repository retries explicitly

`pager/sync_page_file_linux.go:syncPageFileData` retries `EINTR` in a repository-owned loop and falls back to `file.Sync()` for `ENOSYS/EINVAL`. Calling it once is not fixed repository work. A native-only Linux primitive should perform exactly one `unix.Fdatasync(int(file.Fd()))` plus `runtime.KeepAlive(file)`, returning the exact error. The pinned x/sys `unix/zsyscall_linux.go:Fdatasync` has one syscall invocation and no source retry. Use this primitive for BOTH the retained-index native callback and `WritePrimaryCapsuleWithTypedFenceStatusV6`; ordinary calls continue through the unchanged original helper/test hook.

Any such error after adoption, including EINTR/ENOSYS/EINVAL, follows the selected sticky recovery-required policy. Before the capsule is copied it is known unfenced; after copy begins retain original ambiguous-authority disposition. Do not retry, fallback, cancel/abort adopted output, ACK, clear pending custody, or replay on repeated Close. This explicitly sacrifices native availability relative to ordinary sync. A failed capsule fence keeps its original mutation=true classification. No syscall wall-time bound is implied.

`os.File.Stat` is also not one syscall attempt: pinned Go1.26.3 `os/stat_unix.go` calls `internal/poll.FD.Fstat`, whose `ignoringEINTR` retries. Preferred native extent observation is one `unix.Fstat` into a call-local `unix.Stat_t`, followed by KeepAlive and the existing `durableFileSize.Store`; return its error without fallback. This retains the successful extent update without a new heap FileInfo object or repository retry. If using ordinary `File.Stat` instead, its standard-library retries and allocation must be explicitly accepted as the runtime-service boundary rather than described as a single syscall. The direct Fstat proposal avoids that additional accounting choice.

Capability must be proven on both original captured pagers and the authority capsule pager before activation: Linux file-backed operation, supported single-attempt primitive, observers disabled, original canonical noncancellable context policy, same admitted native callback/retained descriptor and supported geometry. Non-Linux mapped-flush-required routes reject before activation; a bare FD sync cannot substitute for their actual mapped flush. No portable finite claim is made. All effect-free capability checks remain charged, and final mutable basis is revalidated by the original turn.

## Exact source work that the new formula must include

For each retained-index barrier: finite callback dispatch and validation; lock acquisition/release and fixed pager/file operands; descriptor extraction; one Fdatasync invocation and KeepAlive; one Fstat invocation and KeepAlive; scalar extent store and error/return control. Include `unsafe.Sizeof(unix.Stat_t{})`, actual pager/file/descriptor operands, and fixed traffic using the implementation's actual source expressions. Keep original token wrapper records for its clocks, metrics and frontier test. No term depends on dirty count/span/concurrency, because the route never inspects or traverses that collection. Disabled observation checks still count; enabled observations are rejected before activation.

For the capsule: retain actual typed header/fence dispatch, fixed geometry/image checks, actual three image iterations/copies, one verified-word store, dirty marking, original fault guard, one Fdatasync, one Fstat, extent store, mutation/error control, and original authority scope/failure budget. Do not reuse an index fence as capsule authority. All callback traffic and error disposition capacity must fit the same pre-effect final-turn minimum; individual reservations remain on the original grant. No numeric record/byte values are claimed until these actual source operations are implemented and reviewed.

Minimal implementation set: pager `write_work.go`; the finite stable-file entry in `pager.go` or one narrowly factored native pager file; Linux single-attempt helper and non-Linux unsupported capability stub; existing `db/stable_pager_owned_operations.go` dispatch/capability binding; original pre-activation final-basis/driver checks. Token/Set/receipt structures and ownership are unchanged. Add only focused pure pricing/capability/refusal and syscall error controls within the permitted runtime scope; real publication controls still require root authorization.

## Other connected final-driver gap remains

`EnqueueNativeBuiltWithWorkV6` and `BeginNativePublicationTurnV6` remain separate coordinator critical sections. A return-to-return no-yield sequence is insufficient: an ordinary builder, dispatch, or pending tail can change the second call's eligibility after native activation. The narrow required source change is to preadmit the original begin clock/notification/control and initialize the SAME attempt/receipt turn in the enqueue critical section after its last fallible activation/consumption boundary. Ordinary Enqueue remains available after that mutex is released. This is distinct from these pager proposals and still needs root's coherent source disposition. Current Complete plan/head detach, logical Set handoff and physical Finish remain unchanged by A/B.
