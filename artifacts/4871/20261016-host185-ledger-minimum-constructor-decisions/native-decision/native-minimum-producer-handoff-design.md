Vacuum checks its allowed count at `vacuum_online.go:555–560` and again under its cutover gate at1390. A recoverable-root vacuum permits its own one stable capture, not an additional native capture. Thus a live native cursor cannot have current DATA generation replaced while its original capture/callback holds this pin. This is stronger than the general public MinPinnedSnapshotCommitSeq contract. Initial/read-only startup and offline construction do not concurrently publish a second live generation into this DB. Any supported overlay/foreign provider must retain the original physical source's existing protection; an unregistered cross-pager DATA alias would invalidate the proof and must not be admitted as an exception.

## Concrete sufficient invariant

For each generation g, every *exposed source capability* capable of later causing a registry registration at sequence q owns a live guard in g.registry at an immutable s<=q before exposure. “Exposed” includes source descriptors reachable by recovery/capture/coordinator APIs, not just current Snapshot readers. The guarded value is the actual source/DATA floor, not the caller's MVCC timestamp or latest CommitSeq. Exact source identity, generation and guard handle travel together.

A new exposed source either (a) retains the SAME original ancestor guard throughout its deferred construction/transfer, or (b) installs its own guard while that ancestor guard is still live. Its new floor cannot be below the ancestor floor. Recovery installs the initial complete guard set before the DB/view is published. A child reader/directory/capability registers while its source guard remains live; native partial birth retains that original guard borrow across yields until real registration succeeds or genuine cancellation settles the capture. A source guard is removed only after no unregistered future child can escape from that source. Do not release a parent's last guard just because a wrapper was copied or a candidate became visible.

Proof for a **coherent** local registry read: let M be its true minimum including guards and readers. Each new registration/guard at q has an already-live covering guard s<=q, hence q cannot lower M; deletion cannot lower M; live guard sequences are immutable. Consequently an observed minimum m remains conservative for later DATA reuse in that same physical generation. New current-view acquisitions and their completed registrations no longer require global epoch restart. Completed-result reuse after the containing phase4 tail refuses is also safe under this invariant; request/stale-root validation remains independently required before publication.

This proof does NOT justify a registry slot scan split across yields. Example: reader scans empty slot A; an unscanned guard at B covers q; child q is installed into recycled A and B is removed before B is visited. True minimum never decreased, but the split scan missed it. Keep original r.mu-coherent MinPinnedSeqWithWorkV6 or add a genuinely maintained coherent minimum within the SAME registry. No watcher/global registry is needed.

## What is and is not monotone in existing source

The original accepted current DATA generation sequence is retained by PRIMARY-only publication; real DATA materialization uses next.CommitSeq and supplies generation.CommitSeq to the new primaryStateRoot (`root_publication_activation.go:780–812,911`). This supports a source-parent non-lowering proof for ordinary current-view succession within one fixed DATA file. It does NOT mean every future registration uses the latest current floor. A late RecoverableRootSet can register an older slot/proof floor; an older source directory can register its source sequence. Across vacuum replacement, rebuilt DATA deliberately uses the earliest retained source record's sequence (`durable_primary_rebuild_v5.go:56–63`), so no global monotonic floor across physical generations is assumed.

Current-only guard counterexample: current DATA floor is newer, an older inactive slot/proof remains available but unguarded, a minimum is observed, then RecoverableRootSet registers the historical floor. Guarding that historical role at its original slot/proof constructor prevents this. Guarding only at later set capture does not. Moving an old source into an already-scanned different generation also defeats a general rolling scan; same-idx rejection/native generation exclusion are essential to the narrow algorithm.

Important scope correction to the earlier quiet-epoch account: snapshotAcquireEpoch is an acquisition protocol, not an epoch for all registry producers. Set.RegisterWithHint at436 and DATA-directory Register at47 do not themselves increment it. Therefore source01 quiet-acquisition epochs alone do not establish safety for arbitrary late lower non-Snapshot registrations. Earlier controlled quiet-epoch results remain historical in their tested producer scope; they are not proof of this unimplemented role-complete invariant.

## Smallest remaining decision and discriminating controls

Select the source-role handoff protocol and local DATA capability domain first. This removes whole idxAll discovery and the need for the native consumer's two acquisition-shard scans without adding a new owner or observer registry. Do not merely remove those scans from current source.

Preserve the existing coherent registry query initially where its actual geometry fits. It currently charges17 records plus len(seqs) when dirty (`lifecycle/registry.go:229–253`); fast-cohort first claim is serialized with that query, positive-cohort joining does not lower it. Arbitrary ordinary fallback history can make this indivisible unit exceed Q32; adding guards can itself exhaust16 fixed cohorts. Neither an inferred cardinality cap nor refusing formerly supported ordinary readers is acceptable. For general quantum-scaled progress, the first remaining representation prerequisite is a bounded incrementally maintained combined minimum/last-removal authority in THIS ReaderRegistry, with admitted backing and real removal work. `r.min` alone excludes fast cohorts and may be dirty; a never-raising minimum is permanent over-retention. No specific replacement or implementation is selected here.

A narrow control set must pause a genuine partial native birth before registration, supersede its view with real DATA then PRIMARY-only commits, and verify original guard overlap; capture an older inactive slot and each parent proof after the consumer has observed current registry; exercise pending/ambiguous original custody and failed/cancelled handoffs; retain an old directory and old reader; and interleave actual reader births with durable commits at every public yield. Require local minimum progress with actual per-entry work and unchanged request/stale/Finish oracles. Add a negative missing historical-role guard and a recycled-slot split-scan control. A separate generation-swap attempt must fail while original stable capture is live and resume only after original callback completion. No tests/runs were performed for this advice.

Guard handles/refcounts/independent controls and any registry backing are charged before allocation/effects in their ORIGINAL Snapshot/root/member/slot/lease metadata domains. Refusal keeps old guard and parent custody; rollback drops only genuinely acquired edges. Guard withdrawal/last-drop, aggregate maintenance and any growth are charged work through last aliases, including partial native cancellation and physical-error custody. RootReuse/registry lock order must remain original; no callback under registry lock may reenter registry or acquire publication locks in reverse order. Fixed fast-cohort CAS retries are not silently declared bounded. Ordinary hot-path allocation/lock cost changes need source-bound validation and matched cost evidence. This advice supplies neither numeric grant nor Q32/publication/Finish/continuing-writer qualification.
