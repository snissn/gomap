# Close notification Windows test repair

Scope: only `TreeDB/cow_close_notification_test.go` changed on parent commit `61fbd36655a9a8641f1cacee013c8f2bf2dc1553`. Public Close/read admission and storage code are unchanged. No commit, push, GitHub mutation, benchmark, or remote job was performed.

The original hosted Windows job112177573211 failed the old test's five-second watchdog around **all of Close**, then removed its TempDir while the unjoined Close goroutine still owned files. The retained log contains no notification-entry or read-completion signal. It therefore does not establish a callback lifecycle deadlock. Adjacent approximately eight-second passing tests include checkpoint/Close/reopen, and are not isolated Close latency measurements. The original log/hash is bound by `before-source.json`; its actual test events are retained separately without rewriting the original failure.

Source order: public Close first stops background maintenance and closes maintenance; it then owns lifecycleMu, invokes the final command-WAL checkpoint, synchronously reportError/NotifyError on failure, and only afterward closes cached/backend/dictionary storage. Stats and captureReadOwners use TryRLock and must refuse admission during that notification. This supports a test classification/ownership repair; no concrete current runtime defect was demonstrated.

The repaired test still fills the real finite COW external budget, requires the wrapped final-checkpoint ErrCOWCapacity from actual Close, and verifies zero live TotalBytes/ExternalLeases after pressure release. Buffered entry and completion signals surround actual Stats/Get. From entry, the callback retains a five-second read watchdog, and requires nil Stats plus ErrClosed. It waits on an explicit release signal; the test verifies Close has not returned before releasing the synchronous notification. A separate thirty-second whole-storage watchdog covers entry and subsequent teardown, with stage-specific failures. Cleanup releases the callback and pressure and joins the Close owner with a separate finite thirty-second bound before removing its manually owned temporary directory. If that join itself fails, the test reports failure and preserves the directory rather than deleting files owned by an active goroutine. The process-level five-minute Go test timeout remains an outer bound.

This is not a timeout-only waiver: the callback deadline remains five seconds, actual pressure and error identity remain required, synchronous ordering and nil diagnostics are newly asserted, and cleanup ownership is explicit. The thirty-second storage bound is a finite watchdog, not a measured Windows performance threshold or assertion that the old failure was merely a flake. Windows validation remains the hosted CI gate; local targeted runs bind their actual Darwin toolchain/environment and do not claim Windows execution.

Both existing close-notification tests run three times per stage. Exact commands/exits, raw JSON/stdout, stderr, source hashes, and packet hashes accompany this report. Final gate counts and completion source proof appear in the handoff.
