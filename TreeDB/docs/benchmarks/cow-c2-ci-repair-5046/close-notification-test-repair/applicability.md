[The retained original events](local/original-windows-failure-events.json) and [independent diagnosis](independent/close-notification-windows-diagnosis.md) establish a timeout and open-handle cleanup failure, not which Close phase exceeded the watchdog. The original full public CI log remains privately hash-bound; following fixture runtimes are not isolated Close measurements.

Only `TreeDB/cow_close_notification_test.go` changes for this repair. It signals actual callback entry/completion, requires nil Stats and ErrClosed, starts the unchanged five-second callback read deadline at entry, withholds callback release while checking Close has not returned, and separately bounds storage teardown by thirty seconds. Actual returned checkpoint refusal and zero retained-cache charges remain required. Cleanup releases pressure and the gate, joins the Close owner before deleting its directory, and fails while preserving the directory if the bounded join does not complete. The synchronous assertion is a point-in-time observation supported by the unchanged synchronous reportError implementation, not a universal proof about every future callback implementation.
