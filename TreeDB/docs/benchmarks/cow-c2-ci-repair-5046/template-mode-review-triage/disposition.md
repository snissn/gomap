# Public template-mode review disposition

The [exact61 hosted finding](local/review-thread.json) claimed that a non-off public template mode bypassed initial COW validation, then caused caching.Open to refuse after backend/side-store creation. That later refusal is unreachable in current public Open: `forceTemplateCompressionOff` normalizes the mode to off and clears template lookup/read options before directory layout and storage opening. The existing public `TestSideStoreChunkSize_TemplateModeRequestIsIgnored` documents intentional normalization. Direct caching.Open still refuses an effective non-off template mode.

The [literal unchanged-source probe](local/probe.go.txt) exercised all three public COW profiles with both TemplateOnly and TemplatePrepass on absent database directories. [All six rows](local/actual-cow-open.stdout) opened actual cow_btree, created no templatedb and passed SetSync/Get/Close. The existing ignored-template test passed count3. The [exact commands and exits](local/execution-receipts.json), environment and before/after hashes are retained. These are local Darwin results, not new Windows qualification. The probe retains its original bytes as .go.txt and is not a compiled repository package.

The coordinator preserves shared public normalization and dismisses the claimed late-refusal/storage-effect defect with this evidence. Adding caller-mode refusal would introduce a COW-only public policy change. [Independent review](independent/template-mode-preflight-review.md) accepts this disposition. No production or checkout test source changed for the triage, and no historical cost measurements are relabeled. The separate Close test repair changes test compilation inputs; final-head CI/performance/Windows/hosted review remain required.
