## Selected algorithm and ownership

`NativeProducerObservation` is a scalar, comparable value: logical sequence, the existing physical StateToken, optional immutable semantic construction inventory, current reserved bytes/source/generation counts, and the original watermark predicate. It owns no cut, publication authority, allocation lease, snapshot, callback or reservation. Historical peak is omitted. The bridge gains two fixed methods; all current bindings use the existing caching DB implementation. No additional provider or registry is introduced.

`ObserveNativeProducer` calls the unchanged `nativeProducerPressureState` and releases its existing cut edge before returning. That observer still borrows the exact immutable semantic state and paired basis, outside the cut latch, releases that edge on error as well as success, and reads the same budget statistics. It never acquires `nativePressureMu`, checkpoints, or joins the semantic cleanup frontier. Brief original cut/budget/basis read synchronization remains; this is not a lock-free or I/O-free promise. Last-cut withdrawal still performs its existing raw/basis release and queues semantic cleanup; this change does not turn that release into a semantic Finish/frontier join.

`PrepareNativeProducerObservation` is the original producer algorithm with result-bearing successful exits. Below threshold it returns the first observation; recheck/no-pressure/remembered exits return the rechecked observation; successful checkpoint plus original cleanup join returns the final observation. The owned-callback self-join guard, pressure mutex extent, exact no-progress memory and error precedence remain. The old `PrepareNativeProducer` wrapper discards the scalar result. Neither method reserves future headroom.

The new shared collection helper is used only at the four existing one-shot CRUD gates: ordinary insert, batch update, batch delete, conditional single delete. It prepares outside the gate; acquires the original shared collection gate; freshly observes before opening a transaction or invoking a body; and continues if below threshold or exactly equal to the completed preparation. Otherwise it releases the gate and performs the same off-gate preparation before trying pre-opening validation again. The private natural post-preparation phase accepts only the scalar identity, allowing a deterministic test latch without a global test hook or new production callback API.

Lock order is existing collection gate -> non-draining observation -> either original one-shot body or gate release. All pressure-mutex/Checkpoint/frontier waits remain outside that gate. No DB-wide turn spans a request. Different collections and grouped typed producers retain their previous scheduling. The original finite next-state/admission checks remain necessary because unrelated owners can change shared debt after observation. No body/transaction is retried by this loop, and there is no promised progress under arbitrarily changing unrelated ownership. Unchanged pressured state terminates after a completed preparation, including pinned readers. Empty-input paths and plain collection no-gate behavior remain in place. A fresh manager-close check after gate acquisition refuses without opening a transaction and releases the gate.

No cap, 75% watermark, maintenance tranche, workload, ACK, constructor promise, schema, source identity, capture, WAL or replay rule changed. Only value observations cross waits; no new persistent accounting or owner exists.
