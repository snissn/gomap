## Blocking findings

1. **P2: buffered response failures escape the promised sticky error and shutdown synchronization.** In `profile_control.go.txt:261-264`, checking `ResponseWriter.Write` checks admission to net/http's response buffer, not necessarily the final socket flush. Go 1.26.10 `net/http/server.go:1674` flushes response buffers in `finishRequest` after the handler returns and discards those flush returns. The helper's `handlers.Done` likewise runs before that framework finalization, so `Close` can observe the handler complete and close its active socket while the response is still buffered. `Server.Close` returns listener-close errors, not these connection-write failures. A physically successful phase can therefore leave successful phase receipts and a zero gateway exit despite a failed control response, contrary to `PRODUCER.md:112-114` and the claimed propagation contract. This is a source-level path, not an observed runtime failure. Before acceptance, explicitly complete and check response flushing inside the tracked handler (including response framing/final bytes), retain that error, and retain a future socket-disconnect/concurrent-stop-close integration control. A checked local flush still does not establish client receipt; the future controller must independently veto its own failed control exchange.

2. **P2: some invalid controls bypass the fail-closed handler.** `profile_control.go.txt:128-133` installs a `ServeMux`, so net/http can choose its canonical-path redirect before `c.admit`; e.g. an incoming POST path `/x/../start?mode=off` is redirected rather than reaching the sticky-error path. Separately, the server's default general `OPTIONS *` handler bypasses the configured handler. Neither request poisons the one-run capture, and a later ordinary start/stop can succeed, contrary to the helper's “all invalid controls” comment and `PRODUCER.md:78-81` non-POST/unknown-route promise. Before acceptance, route parsed requests directly through the admission/validation handler, disable the general OPTIONS shortcut, and cover canonical-path and asterisk requests in future integration controls. Describe the contract as applying to requests that reach application validation; net/http can still reject malformed framing before an application handler runs.
